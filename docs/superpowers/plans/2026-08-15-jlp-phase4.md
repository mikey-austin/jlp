# JLP Phase 4 (Ecosystem: Tools, A2A, Channels, Conversation, Speech, Outcomes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the PRD — a typed tool registry with per-agent permissions and inspectable agent traces, A2A as an integration boundary, messaging channels, an interactive conversation tutor, advanced spaced retrieval, speech, and the learning-outcome analytics that answer the product's real question: *did the teaching actually make the learner more independent?*

**Architecture:** Same modular monolith, extended by addition. Agents gain multi-turn tool calling through a new `ai.ToolCaller` capability alongside the existing `ai.StructuredGenerator`; tools are the ONLY way an agent touches state (PRD Rule 3/§28), each with a JSON Schema and a per-agent allowlist (§64). Every agent run is traced (`agent_runs` + `tool_calls`, §50). Channels are adapters behind one `channels.Channel` port — the domain never learns whether an interaction came from the PWA, Slack, or Signal (§20). A2A exposes selected agents over a protocol boundary without becoming a second source of truth for learner state (§30, Rule 13).

**Tech Stack:** unchanged plus: `github.com/slack-go/slack` (Socket Mode), `signal-cli` (sidecar container, JSON-RPC), whisper.cpp or an equivalent local STT server (sidecar), browser `MediaRecorder` for capture.

**Reference docs:** roadmap `docs/superpowers/plans/2026-08-14-jlp-roadmap.md` §Phase 4; spec `docs/superpowers/specs/2026-08-14-jlp-platform-design.md`; PRD §17.4, §20, §27–§30, §50, §52, §54, §64–§66, §72–§73.

## Global Constraints

- All Phase 1–3 conventions binding: everything via `make` (Go toolchain only in containers); four gates (`test`, `test-integration`, `lint`, `arch-check`) green before every commit; TDD with RAW RED/GREEN evidence; `make test` fully offline (no keys, no network, no live broker); rune-safe text handling with Japanese test strings; identity scoping on every learner-owned query; events via `learning.Recorder` (append-durable, publish-absorbed); migrations numbered in `internal/adapters/postgres/migrationsfs/` (`ls` for the next free number); `make sqlc` output committed; prompts and schemas are versioned files and **fakeai must cover every new schema** (routed on `req.SchemaName`) so dev and CI never need a key.
- **Browser verification by the implementing subagent via claude-in-chrome at http://localhost:28080** for every UI surface, in BOTH themes. New UI uses the design system vocabulary (`tokens.css`/`components.css`); **no colour literals outside `tokens.css`** — the phase-closing sweep will check.
- **One writer at a time.** Only one implementation subagent runs at a time this phase; stage commits by EXPLICIT PATH, never `git add -A`.
- External side effects stay opt-in and config-gated OFF by default (PRD §65): Slack, Signal, WhatsApp, A2A and speech each boot dormant with no credentials, and the app must start clean without them.
- New event constants go in `internal/domain/event/event.go` AND in `event.AllTypes()` (its AST drift test will fail otherwise — that is intentional).
- Agents may import only `ports/ai`, `prompts`, `schemas`, `internal/agent/aiutil`, and `internal/domain/**` (depguard enforces). Tools are the agents' only route to state.

type ToolDef struct {

}
type ToolInvocation struct{ ID, Name string; Arguments json.RawMessage }
type ToolResult struct{ ID string; Content string; IsError bool }
type ToolTurn struct {
	Text        string           // assistant prose for this turn (may be empty)
	Invocations []ToolInvocation // empty ⇒ the model is done
}
type ToolRequest struct {
	PromptName, PromptVersion string
	System                    string
	Messages                  []ToolMessage // conversation so far
	Tools                     []ToolDef
	MaxTokens                 int
	IdentityID                learner.IdentityID
	SessionID                 *session.ID
	Agent                     string
}
type ToolMessage struct {
	Role    string // "user" | "assistant" | "tool"
	Text    string
	Invocations []ToolInvocation // assistant turns
	Results     []ToolResult     // tool turns
}
type ToolResponse struct {
	RequestID string
	Turn      ToolTurn
	Provider, Model string
	InputTokens, OutputTokens int
	Latency time.Duration
}
type ToolCaller interface {

// internal/tools — the registry. Tools are the ONLY route from an agent to state (Rule 3).
type Tool struct {

}
type Registry struct{ /* name → Tool, agent → allowed names */ }
func NewRegistry() *Registry
func (r *Registry) Register(t Tool)
func (r *Registry) Allow(agent string, toolNames ...string) // per-agent allowlist (PRD §64)

func (r *Registry) Invoke(ctx context.Context, agent string, identity learner.IdentityID, sessionID *session.ID, inv ai.ToolInvocation) ai.ToolResult

type RetrievalItem struct {
	IdentityID learner.IdentityID
	SubjectType string // "concept" | "expression"
	Subject     string
	Successes, Failures int
	LastSeen, DueAt time.Time
	Interval time.Duration
	Confidence float64 // last reported confidence, 0 when unknown
}
type RetrievalRepository interface {
	Upsert(ctx context.Context, it RetrievalItem) error
	Due(ctx context.Context, identity learner.IdentityID, at time.Time, limit int) ([]RetrievalItem, error)
	Get(ctx context.Context, identity learner.IdentityID, subjectType, subject string) (RetrievalItem, error)
	List(ctx context.Context, identity learner.IdentityID, limit int) ([]RetrievalItem, error)
}

// application/retrieval
func NewScheduler(repo storage.RetrievalRepository, clock func() time.Time) *Scheduler
func (s *Scheduler) RecordOutcome(ctx context.Context, identity learner.IdentityID, subjectType, subject string, success bool, confidence int) error
// Interval policy (PRD §54 inputs: previous success/failure, elapsed time, production
// frequency, confidence, importance) — deterministic and test-pinned:
//   base intervals 1d, 3d, 7d, 16d, 35d, 90d (index by consecutive successes, capped)
//   success  → advance one step; failure → drop two steps (min 0)
//   confidence 1–2 on a success → do NOT advance (shaky knowledge repeats sooner)
//   confidence 5 on a success → advance two steps
