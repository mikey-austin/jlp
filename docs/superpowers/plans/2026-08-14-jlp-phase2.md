# JLP Phase 2 (Adaptive Teaching Engine) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the adapt loop — grammar concept tracking, a learner model with observations/priorities feeding the teacher, vocabulary ingestion + expression activation, active recall with hints and confidence, a drill engine, an AI quality dashboard, multi-provider AI (Ollama + routing + CLI adapters), and an evaluation corpus.

**Architecture:** Everything extends the Phase 1 hexagonal monolith by addition (PRD Rule 15): new domain packages (grammar, vocabulary), new event consumers behind the existing bus, new prompts/schemas as versioned data, new AI adapters behind the existing `ai.StructuredGenerator` port, new pages on the existing chi/HTMX server. No existing interface changes except where a task explicitly says so.

**Tech Stack:** unchanged from Phase 1 (see spec §3). New: `gopkg.in/yaml.v3` (catalog data files), Ollama HTTP API (no SDK — plain net/http).

**Reference docs:** roadmap `docs/superpowers/plans/2026-08-14-jlp-roadmap.md` (§Phase 2 is the source of these tasks); spec `docs/superpowers/specs/2026-08-14-jlp-platform-design.md`; PRD §9–§17, §23–§26, §48–§49, §53, §55.

## Global Constraints

- All Phase 1 conventions are binding and unchanged: every command through `make` (toolchain only in containers); TDD with RED/GREEN evidence; `make test` + `make test-integration` + `make lint` + `make arch-check` green before every commit; `make test` never needs a live AI key or network; rune-based text handling with Japanese test strings; identity scoping on every learner-owned query (Rule 6); migrations in `internal/adapters/postgres/migrationsfs/` (next number 00008), queries in `db/queries/`, `make sqlc` regenerates committed `sqlcgen`; pgtype conversion helper patterns live in the existing postgres adapters; sentinel `storage.ErrNotFound`; events recorded via `learning.Recorder` (append-durable, publish-absorbed — see `internal/application/learning/recorder.go` doc comment).
- **Browser verification by the implementing subagent via claude-in-chrome is mandatory** for every task with a UI surface, at http://localhost:28080 on this machine (`APP_HOST_PORT=28080` in local `.env`; default 8080 elsewhere).
- Prompts are versioned files — never edit a released version; add `vN+1` (Rule 10). Schemas likewise (`internal/schemas/defs/`).
- fakeai (`internal/adapters/fakeai`) must keep dev/browser flows and tests working offline for every new AI capability — every task that adds a prompt/schema also extends fakeai deterministically.
- New reference-data files live under `data/` (committed); loaded via the `seed` subcommand or embedded loaders as each task specifies.
- depguard: new packages get rules consistent with `.golangci.yml` (domain purity; agents import no storage/adapters; application imports no adapters); update the config in the same task that creates a package the rules must cover.
- Event type constants: extend `internal/domain/event/event.go` — never inline string literals.
- IDs `github.com/google/uuid` v4 strings unless a table says otherwise.

```sql
-- name: ConceptStats :many
SELECT gc.slug, gc.name, gc.jlpt_level,
       COUNT(cc.correction_id)::int AS encounters,
       COALESCE(MAX(c.created_at), 'epoch'::timestamptz) AS last_seen
FROM grammar_concepts gc
LEFT JOIN correction_concepts cc ON cc.concept_slug = gc.slug AND cc.resolved
LEFT JOIN corrections c ON c.id = cc.correction_id
LEFT JOIN feedback_requests f ON f.id = c.feedback_request_id AND f.identity_id = $1
WHERE f.id IS NOT NULL OR cc.correction_id IS NULL
GROUP BY gc.slug, gc.name, gc.jlpt_level
ORDER BY encounters DESC, gc.jlpt_level DESC, gc.slug;
```

- **Detection rules (deterministic, test-pinned):**
  - *Weakness:* on each `correction.presented` or `grammar.concept.encountered` event, count that subject's occurrences in the trailing 30 days (from the event store): ≥3 with severity `incorrect`|`unnatural` (correction-type subjects use Evidence type; concept subjects count concept events) → upsert `weakness` with Evidence `{"count":N,"window_days":30}`.
