# JLP Phase 3 (Reach: Extension, Anki, Tutors, Email, MQTT) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the platform's reach beyond the PWA — Chrome extension, Anki card generation, human-tutor lesson guides, weekly email summaries, MQTT event bridging with external reading-app ingestion, and richer analytics — plus the hardening items Phase 2's final review queued.

**Architecture:** Every channel is an adapter of existing application services (PRD §20 — the domain never learns where an interaction came from). New agents (anki, lesson, summary) follow the teacher/drill single-shot pattern over `ai.StructuredGenerator` with versioned prompts/schemas and fakeai coverage. MQTT bridges the in-process bus (Rule 7/8: transport-independent envelope). External side effects (email send, AnkiConnect push) are config-gated OFF by default (PRD §64/65).

**Tech Stack:** unchanged plus: `github.com/eclipse/paho.mqtt.golang` (MQTT client), `github.com/robfig/cron/v3` (in-app scheduler), Eclipse Mosquitto 2 (compose), Mailpit (compose). Chrome extension: hand-rolled MV3, zero build tooling (plain JS, mirrors the vendored-asset philosophy).

**Reference docs:** roadmap `docs/superpowers/plans/2026-08-14-jlp-roadmap.md` §Phase 3; spec `docs/superpowers/specs/2026-08-14-jlp-platform-design.md`; PRD §12, §18–§21, §31–§33, §40, §51, §59–§60.

### Task 1: Phase-opening hardening

**Files:**
- Create: `internal/adapters/http/csrf.go`, `internal/adapters/http/csrf_test.go`
- Modify: `internal/adapters/http/server.go` (mount CSRF middleware on the auth group), `internal/domain/grammar/concept.go` + test (cross-ref validation), `data/grammar/concepts.yaml` (fix any dangling refs the new validation finds), `internal/application/learnermodel/consumers_test.go` (flip-back regression test), `cmd/jlp/eval.go` + test (like-with-like baseline)
- Test: listed above

**Interfaces:**
- Consumes: existing middleware chain; `grammar.LoadCatalog`; learnermodel Updater; eval report summary struct.
- Produces: `httpx.CSRFProtect() func(http.Handler) http.Handler` — applied to the authenticated group BEFORE route handlers.

Semantics (each independently small):
1. **CSRF (origin-verification, not tokens):** for state-changing methods (POST/PUT/PATCH/DELETE), reject with 403 `{"error":"cross-origin request rejected"}` (JSON for /api/*, plain otherwise) when `Sec-Fetch-Site` is present with value `cross-site`; else when `Origin` is present and its host:port ≠ the request's `Host` → reject. These pass: same-origin; `Sec-Fetch-Site: same-site|none`; header-absent (curl and other non-browser clients); **`Origin` with scheme `chrome-extension:` or `moz-extension:`** (browser extensions send their own origin — Task 2's extension depends on this); **`Origin: null`** (opaque origins — `file://` pages and sandboxed iframes; accepted for a LAN-scoped app, with a comment stating the tradeoff). Test-pinned: cross-site blocked via both header forms; same-origin passes; headerless passes; `chrome-extension://abc` passes; `null` passes; GET never blocked.
2. **Catalog cross-refs:** `LoadCatalog` validates every `related`/`prerequisites` slug exists in the catalog; error names the dangling ref. Fix any real dangling refs the validation exposes in `concepts.yaml`.
3. **Flip-back regression test:** an `emerging` observation whose subject accrues 3 fresh qualifying occurrences flips back to `weakness` (behavior exists; pin it).
4. **Eval baseline like-with-like:** the regression comparison only considers the most recent prior report with the SAME provider+model; when none exists, print "no comparable baseline" and exit 0. Test-pinned with mixed-provider report files.

- [ ] **Step 1: TDD each item (RED → GREEN), four gates.**
- [ ] **Step 2: Browser verification.** Normal app flows still work end-to-end (feedback round + practice round — CSRF must not break same-origin htmx/fetch); a forged cross-site POST via javascript_tool `fetch` from a different-origin page is impractical to simulate in-tab, so pin CSRF at the handler-test level and verify in-browser only that nothing regressed. Console clean.
- [ ] **Step 3: Commit** — `"feat: origin-based CSRF protection and phase-2 review hardening"` (+ trailer).

func NewBridge(url string, bus events.EventBus, vocab *vocabulary.Service, identities storage.IdentityRepository) (*Bridge, error)

//   (e.g. writing, correction, vocabulary, quiz, grammar, feedback, hint, answer, confidence, tutor, anki),
//   payload = JSON {id, identity_id, session_id, type, subject, evidence, occurred_at} (transport-independent envelope).

- `mosquitto.conf`: listener 1883 on the compose network, `allow_anonymous true` (LAN dev; note prod would add auth), persistence off.
